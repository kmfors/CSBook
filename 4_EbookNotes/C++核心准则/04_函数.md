C++ Core Guidelines 第四章“函数”（Functions）主要涵盖了函数设计和使用的 **最佳实践**，核心目标是提高代码的 **安全性、清晰性、可维护性和性能**。

以下是该章节的主要内容要点：

## 核心原则：让函数职责明确且简单

函数定义：

   * F.1: 将有意义的操作封装成精心命名的函数
   * F.2: 一个函数应只执行一个逻辑操作（单一职责原则）
   * F.3: 保持函数短小简洁（建议不超过一屏，约 60 行）
   * F.4：如果函数有可能需要在编译期求值，就把它声明为 constexpr
   * F.6：如果你的函数必定不抛异常，就把它声明为 noexcept
   * F.8：优先使用纯函数



参数传递：入与出

- F.15：优先采用简单而约定俗成的信息传递方式
- F.16：对于“入”参，拷贝开销低的类型按值传递，其他类型则以 const 引用来传递
- F.19：对于“转发”参数，要用 `TP&&` 来传递，并且只 `std::forward` 该参数
- F.17：对于“入-出”参数，使用非 const 引用来传递
- F.20：对于“出”的输出值，优先使用返回值而非输出参数
- F.21：要返回多个“出”值，优先考虑返回结构体或者多元组

值返回语义

- F.42：返回T*（仅仅）用于表示位置
- F.44：当不希望发生拷贝时，也不需要表达“没有返回对象”时，应返回T&
- F.45：不要返回 T&&
- F.48：不要返回 std::move（本地变量）
- F.46：main() 的返回类型是int

- F.50：当函数不适用时（需要捕获局部变量时，或编写一个局部函数），请使用lambda表达式
- F.52：在局部使用（包括传递给算法）的lambda表达式中，优先通过引用来捕获
- F.53：在非局部使用（包括要被返回、存储在堆上或要传给其他线程）的lambda表达式中，避免通过引用来捕获
- F.51：在有选择的情况下，优先使用默认参数而非重载
- F.55：不要使用 va_arg 参数

## 函数接口设计（重点）
   * **参数传递：**
     * **F.15: 优先按值传递简单、可移动、可复制的参数**（对于“入”参数，当函数需要副本时）。
     * **F.16: 对于“入”参数，如果函数不需要获得所有权，且参数不可拷贝/移动成本高，则通过 `const` 引用传递**。
     * **F.17: 对于“入出”参数，通过非常量引用传递**。
     * **F.20: 对于“出”参数，优先使用返回值而非输出参数**。这是现代 C++的重要风格转变。
     * **F.21: 如果需要返回多个“出”值，优先使用 `tuple` 或 `struct`，而非输出参数**。
   * **所有权与智能指针：**
     * **F.22: 使用 `T*` 或 `owner<T*>` 表示“单个”对象的所有权**（`owner` 是 GSL 中的概念，用于标记原始指针的所有权）。
     * **F.23: 使用 `unique_ptr` 传递独占所有权**。
     * **F.24: 使用 `span` 传递数组**，而不是 `T*` 或 `T&` 加大小参数。
     * **F.25: 使用 `shared_ptr` 共享所有权时应慎重**，通常用于共享生命周期的情况。
   * **避免复杂接口：**
     * **F.4: 如果一个函数可能需要在没有参数的情况下被调用，应使用函数重载，而不是默认参数**（因为默认参数在调用点不可见，且可能引发歧义）。

### 3. **返回值设计**
   * **F.44: 当函数不失败或失败无法恢复时，返回 `T`**（按值返回）。
   * **F.45: 不要返回 `const T`**（这会阻止移动语义，且通常无意义）。
   * **F.46: `main` 函数的返回类型是 `int`**。
   * **F.47: 返回 `T&` 时需谨慎**，确保不会返回局部对象的引用或悬空引用。

### 4. **函数语义与 `noexcept`**
   * **F.6: 如果函数可能抛出异常，应声明其可能抛出的异常类型**（但实践中更多使用 `noexcept` 来标记不抛异常）。
   * **F.8: 优先使用 `noexcept` 标记不抛出异常的函数**（这有助于优化，并让接口更明确）。

### 5. **函数重载与泛型**
   * **F.50: 当算法在不同类型上工作逻辑相同时，使用函数模板**。
   * **F.51: 当需要根据类型选择不同实现时，使用函数重载**（例如，针对特定类型优化）。
   * **F.52: 优先使用重载而非默认参数来定义语义不同的函数**。

### 6. **Lambda 表达式**
   * **F.52: 在局部作用域（算法内部、回调）中使用 Lambda**，避免定义只在一处使用的命名函数对象。
   * **F.53: 避免使用捕获列表为默认引用的 Lambda（`[&]`），除非作用域很小或生命周期明确可控**，防止悬空引用。
   * **F.54: 当 Lambda 可能逃逸当前作用域（如被存储或传递到线程）时，避免捕获局部变量引用**。

### 7. **杂项重要规则**
   * **F.9: 未使用的参数应匿名**（例如 `void foo(int /*unused*/)`）或加上 `[[maybe_unused]]` 属性。
   * **F.10: 如果函数在编译时已知条件，使用 `constexpr`**。
   * **F.27: 使用 `shared_ptr` 作为共享所有权的智能指针，但需注意其开销**。

### 8. **与错误处理相关**
   * **F.10: 错误处理应通过异常（或 `expected` 等类型），而不是通过错误码或全局状态**（如 `errno`），这与其他章节（如错误处理）紧密相关。

### 总结
第四章的核心思想是：**函数应该是接口清晰、职责单一、资源所有权明确、且异常安全的**。它强烈鼓励：
* 使用 **返回值** 而非输出参数。
* 使用 **现代类型**（如 `span`、智能指针）来明确语义。
* 通过 `const`、引用、值传递等方式 **精确表达参数意图**。
* 保持函数 **短小、可测试、可维护**。

这些规则共同服务于 C++ Core Guidelines 的总体目标：让 C++代码更 **类型安全、资源安全、高效且易于理解**。
