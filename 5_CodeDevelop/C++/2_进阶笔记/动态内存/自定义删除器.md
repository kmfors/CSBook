# 智能指针自定义删除器

## 不同资源的释放需求

在使用智能指针管理资源时，我们需要针对不同创建方式指定对应的释放方式：

| 创建方式    | 释放方式       | 适用场景      |
| ----------- | -------------- | ------------- |
| `new`       | `delete`       | 普通对象      |
| `new[]`     | `delete[]`     | 对象数组      |
| `malloc()`  | `free()`       | C 风格内存分配 |
| `fopen()`   | `fclose()`     | 文件操作      |
| `socket()`  | `close()`      | 网络套接字    |
| 其他系统 API | 对应的释放函数 | 系统资源      |

## 自定义删除器的实现方式

### 1. 函数对象（推荐）

```cpp
struct FILECloser {
    void operator()(FILE* fp) const {
        if(fp) {
            fclose(fp);
            std::cout << "File closed\n";
        }
    }
};

// 使用示例
void test_file() {
    std::unique_ptr<FILE, FILECloser> up(fopen("test.txt", "a+"));
    // 文件会在up离开作用域时自动关闭
}
```

### 2. Lambda 表达式（C++11+推荐）

```cpp
void test_lambda() {
    auto deleter = [](FILE* fp) {
        if(fp) {
            fclose(fp);
            std::cout << "File closed via lambda\n";
        }
    };
    
    std::unique_ptr<FILE, decltype(deleter)> up(fopen("test.txt", "a+"), deleter);
}
```

### 3. 函数指针（不推荐）

```cpp
void close_file(FILE* fp) {
    if(fp) {
        fclose(fp);
        std::cout << "File closed via function\n";
    }
}

void test_func_ptr() {
    // 需要显式指定删除器类型
    std::unique_ptr<FILE, void(*)(FILE*)> up(fopen("test.txt", "a+"), close_file);
}
```

## `unique_ptr` vs `shared_ptr` 删除器差异

| 特性           | `unique_ptr`                   | `shared_ptr`             |
| -------------- | ------------------------------ | ------------------------ |
| 删除器指定位置 | 模板参数                       | 构造函数参数             |
| 类型影响       | 删除器类型影响智能指针类型     | 删除器不影响智能指针类型 |
| 性能           | 零开销（可能编译期优化）       | 有小额外开销             |
| 典型用例       | 需要高效、独占所有权的资源管理 | 需要共享所有权的场景     |

### `shared_ptr` 删除器示例

```cpp
void test_shared_ptr() {
    auto deleter = [](FILE* fp) {
        if(fp) {
            fclose(fp);
            std::cout << "File closed in shared_ptr\n";
        }
    };
    
    std::shared_ptr<FILE> sp(fopen("test.txt", "a+"), deleter);
    // 类型始终是 shared_ptr<FILE>，与删除器无关
}
```

## 为什么函数指针不推荐？

1. **灵活性差**：需要预先定义函数原型
   ```cpp
   // 必须严格匹配 void(*)(T*) 签名
   void my_deleter(FILE*); 
   ```

2. **可能的内存泄漏风险**：
   ```cpp
   // 容易忘记传递删除器
   std::unique_ptr<FILE, void(*)(FILE*)> up(fopen(...)); 
   // 缺少删除器参数，可能导致未定义行为
   ```

3. **代码可读性差**：
   ```cpp
   // 需要跳转到函数定义查看释放逻辑
   std::unique_ptr<FILE, void(*)(FILE*)> up(fopen(...), &close_file);
   ```

相比之下，lambda 表达式可以内联定义释放逻辑，更清晰直观：

```cpp
auto up = std::unique_ptr<FILE, std::function<void(FILE*)>>(
    fopen(...),
    [](FILE* fp) { /* 释放逻辑直接可见 */ }
);
```

## 实际应用建议

1. **优先使用 lambda 表达式**：简洁直观，适合一次性使用的删除器
2. **复杂逻辑使用函数对象**：适合需要复用的删除逻辑
3. **避免函数指针**：除非必须与旧代码兼容
4. **系统资源管理**：文件、套接字等必须使用自定义删除器
5. **注意删除器异常安全**：删除器中不要抛出异常

正确使用自定义删除器可以让智能指针安全地管理各种资源，是现代 C++资源管理的核心技巧之一。
