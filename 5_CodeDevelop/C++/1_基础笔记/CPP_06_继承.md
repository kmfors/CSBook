## 继承的基础语法

**继承** 是一种代码复用和层次化设计的机制，它通过派生类（Derived Class）继承基类（Base Class）的成员（属性和方法），并允许：

1. **直接复用** 基类的非私有成员
2. **扩展** 新的成员或功能
3. **重写（Override）** 基类的虚函数以实现多态行为

```c++
class Base {
public:
    void baseFunc();
};

// 公有继承
class Derived : public Base { 
public:
    void derivedFunc();
};
```



## 继承方式与访问控制

| 继承方式    | 基类 `public` 成员权限 | 基类 `protected` 成员权限 | 基类 `private` 成员权限 |
| :---------- | :--------------- | :------------------ | :---------------- |
| `public`    | public           | protected           | 不可访问          |
| `protected` | protected        | protected           | 不可访问          |
| `private`   | private          | private             | 不可访问          |

> [!NOTE]
>
> 通过继承，除了基类私有成员以外的其它所有数据成员和成员函数，派生类中可以直接访问。
>
> - `private` 成员是私有成员，只能被本类的成员函数所访问，派生类和类外都不能访问。
> - `public` 成员是公有成员，在本类、派生类和外部都可访问。
> - `protected` 成员是保护成员，只能在本类和派生类中访问，是一种区分血缘关系内外有别的成员。
>
> 总结：派生类的访问权限规则如下：
>
> 1. 不管以什么继承方式，派生类内部都不能访问基类的私有成员。
> 2. 不管以什么继承方式，派生类内部除了基类的私有成员不可以访问外，其他的都可以访问。
> 3. 不管以什么继承方式，**派生类对象** 只能访问公有继承基类中的公有成员，其他的一律不能访问
>
> **注意：如果不写继承方式，那么默认的继承方式都是私有的**。



## 继承的局限

在 C++ 中，**继承机制并非万能**，某些基类的特性确实无法被派生类继承。以下是 **无法通过继承获得的基类特性** 及其原因分析，这些限制对设计类层次结构有重要影响：

### 基类的构造与析构

**构造函数（包括拷贝/移动构造）**：每个类的构造函数必须独立定义。构造函数需要处理类自身的成员初始化，派生类需要额外初始化自己的成员。

**析构函数**：派生类会自动调用基类析构函数。注意：基类析构函数 **必须声明为虚函数**（否则通过基类指针删除派生类对象时会导致资源泄漏）。

### 基类的友元关系

友元关系仅对声明它的类有效，因此派生类无法继承基类的友元关系。

### 基类的静态成员

静态成员属于类本身而非对象，因此派生类会 **共享** 基类的静态成员（而非继承副本）

### 基类的私有成员

无论何种继承方式，派生类都无法直接访问基类的 `private` 成员，但可以通过基类的 `protected/public` 方法间接访问。

### 基类的运算符重载

**赋值运算符**：如果派生类未定义，编译器会生成默认的逐成员赋值，但不会自动调用基类的赋值运算符。

```c++
Derived& operator=(const Derived& rhs) {
    Base::operator=(rhs); // 显式调用基类赋值
    // 处理派生类成员赋值...
    return *this;
}
```

**其他运算符**：需要重新定义，基类的运算符重载对派生类对象无效，除非通过类型转换（通常不推荐）

### 模板参数

基类的模板特化不会影响派生类

```c++
template<typename T>
class Base { /*...*/ };

template<>
class Base<int> { /* 特化版本 */ };

class Derived : public Base<double> {
    // 不会自动获得 Base<int> 的特化特性
};
```



## 派生类对象的构造

**原则**：先构造基类部分，后构造派生类部分。实际上，为了完成从基类吸收而来的数据成员的初始化，需要在派生类的构造函数的初始化列表中，借助基类的构造函数，来完成基类数据成员的初始化。

错误的说法：派生类对象的构造是“先调用基类的构造函数，然后调用派生类的构造函数”。

```c++
class Base {
public:
    int x;
    Base(int val) : x(val) {}  // 基类构造函数
};

class Derived : public Base {
public:
    int y;
    // 正确写法：通过初始化列表初始化基类和成员
    Derived(int a, int b) : Base(a), y(b) {
        // 此处基类和成员已初始化完成
    }
};
```

**对于派生类对象的构造，我们分下面 4 种情况进行讨论**：

1. 如果派生类有显式定义构造函数，而基类没有显示定义构造函数，则创建派生类的对象时，派生类相应的构造函数会被自动调用，同时也将自动调用基类缺省的默认构造函数。
2. 如果派生类没有显式定义构造函数而基类有显示定义构造函数，则基类必须拥有默认构造函数。
3. 如果派生类有构造函数，基类有默认构造函数，则创建派生类的对象时，基类的默认构造函数会自动调用，如果你想调用基类的有参构造函数，必须要在派生类构造函数的初始化列表中显示调用基类的有参构造函数。
4. 如果派生类和基类都有构造函数，但基类没有默认的无参构造函数，即基类的构造函数均带有参数，则派生类的每一个构造函数必须在其初始化列表中显示的去调用基类的某个带参的构造函数。如果派生类的初始化列表中没有显示调用则会出错，因为基类中没有默认的构造函数。

> [!TIP]
>
> 1. 创建派生类对象的时候，会调用派生类的构造函数，但是派生类是继承基类基类的，所以会吸收基类的数据成员。为了完成从基类这边吸收过来的数据成员的初始化，会借鉴基类的构造函数，完成从基类吸收过来的数据成员的初始化，然后再执行派生类的构造函数的函数体。
> 2. 如果派生类没有显式定义构造函数而基类有显示定义构造函数，则基类必须拥有默认构造函数 ，因为派生类的构造函数会默认调用基类的默认（无参）构造函数。目的：就是为了完成吸收的数据成员的初始化。
>
> 总结：在创建派生类对象的时候，为了完成从基类吸收过来的数据成员的初始化，需要使用基类的构造函数，那么最好可以 **手动在派生类的初始化列表中将基类的构造函数显示的调用出来**，这样可以保证代码不出错。

> [!NOTE]
>
> **派生类构造函数的调用顺序：**
>
> 1. 完成对象所占内存的开辟。
> 2. 调用基类的构造函数，完成从基类吸收的数据成员的初始化。
> 3. 完成子对象、const 数据成员、引用数据成员的初始化。
> 4. 执行派生类构造函数的函数体。




## 派生类对象的销毁

当派生类对象被删除时，派生类的析构函数被执行。析构函数同样不能继承，因此，在执行派生类析构函数时，基类析构函数会被自动调用。执行顺序是 **先执行派生类的析构函数，再执行基类的析构函数**，这与执行构造函数时的顺序正好相反。

派生类对象在销毁的时候（离开作用域的时候），会执行派生类自己的析构函数（完成派生类自己数据成员的清理操作）。然后，当派生类的析构函数执行完成之后，**基类的析构函数会被自动调用**。

当考虑类成员对象时，继承机制下派生类析构函数的调用顺序：

1. 先调用派生类的析构函数
2. 再调用派生类中类成员对象的析构函数
3. 最后调用普通基类的析构函数



## 多重继承

多重继承又称多基派生，即一个派生类上层有多个直接基类。在多重继承的派生类定义中，**每个基类都必须单独指定继承方式**，若未显式声明，编译器将默认使用私有继承。

**在此情况下需要注意**：多个基类的构造函数的执行顺序只与多个基类被继承的先后顺序有关，与基类的构造函数在派生类的初始化列表中的先后位置没有关系。

**菱形继承**：如果有两个派生类继承了同一个基类，然后又有一个类同时继承这两个派生类，这种继承我们称之为菱形继承。

![image-20250415170348613](/1_store/1_asset/image-20250415170348613.png)

菱形继承带来的问题：

1. `Singer` 与 `Waiter` 分别继承了 `Person` 的成员；当 `SingingWaiter` 访问 `Person` 成员时，会产生二义性。（**成员名冲突的二义性**）
2. `SingingWaiter` 继承来自 `Person` 的数据有两份，浪费内存。（**菱形继承的二义性**）

### 成员名冲突的二义性

一般来说，在派生类中对基类成员的访问应当具有唯一性，但在多基继承时，如果多个基类中存在同名成员的情况，造成编译器无从判断具体要访问的哪个基类中的成员，则称为对基类成员访问的二义性问题。

解决办法：多基继承（多基派生）成员函数访问冲突时请使用：使用类名 + 作用域限定 进行指定访问。通过作用域，访问具体的类的成员。

缺点：会继承两份数据，浪费内存。

```c++
// 人类
class Person {
public:
	int m_Age;	// 年龄
};
class Singer :public Person {};
class Waiter :public Person {};

class SingingWaiter : public Singer, public Waiter {};
------------------------------------------
// 创建一个SingingWaiter的对象
SingingWaiter sw;

// 问题1： 访问同名成员产生的二义性
sw.m_Age = 200; //报错！该变量不明确！不知道你要访问的是哪一类的人的年龄

sw.Singer::m_Age = 20;  // 通过作用域，访问具体的类的变量
sw.Waiter::m_Age = 30;
	
```

### 菱形继承的二义性

上面没讲到在多基派生中，如果在多条继承路径上有一个共同的基类。那样会继承两份相同的基类数据，浪费内存。

**解决方式**：采用 **虚继承机制**，子类在继承基类时，使用 `virtual` 进行修饰，则是虚继承。

**原理**：

- 虚基类（`Person`）的数据 **只存储一份**，由最底层的派生类（`SingingWaiter`）直接管理。
- 中间类（`Singer` 和 `Waiter`）**只存储一个指向虚基类的指针**（而不是完整对象），避免重复存储。

```c++
class Person {
public:
	int m_Age;	// 年龄
};

class Singer :virtual public Person {};

class Waiter :virtual public Person {};

// 唱歌的服务员
class SingingWaiter : public Singer, public Waiter {};
-----------------------------------------------------
sw.m_Age = 200; //正确，不报错！ m.Age会被两个类所继承
```



## 基类与派生类的类型转换

### 类型适应与转换方向

- **类型适应**：派生类可适应基类，意味着派生类对象能直接用于基类适用的场景（如赋值、传参等），反之不成立。
- **向上转型**：派生类 → 基类（安全，隐式支持）。
- **向下转型**：基类 → 派生类（不安全，需显式强制转换）。

### 向上转型的三种安全场景

1. **对象赋值**：基类对象可直接用派生类对象赋值（发生对象切片，仅保留基类部分）：

   ```c++
   class Base { int _base; };
   class Derived : public Base { int _derived; };
   
   Derived d;
   Base b = d;  // 合法，但b仅保留d的Base部分
   ```

2. **引用绑定**：基类引用可绑定到派生类对象（无数据丢失，通过引用操作派生类中的基类部分）：

   ```c++
   Derived d;
   Base& ref = d;  // 合法，ref引用d的Base部分
   ```

3. **指针指向**：基类指针可指向派生类对象（多态的基础）：

   ```c++
   Derived d;
   Base* ptr = &d;  // 合法，ptr指向d的Base部分
   ```

### 向下转型的风险与安全

1. **语法支持与风险**：C++允许通过强制转换实现向下转型，但存在安全隐患：

   ```c++
   Base b;
   Derived* pd1 = (Derived*)&b;  // C风格强制转换（危险！）
   Derived* pd2 = static_cast<Derived*>(&b);  // static_cast（仍危险！）
   ```

2. **安全向下转型：dynamic_cast**：使用 `dynamic_cast` 进行运行时类型检查（需基类含虚函数）：

   ```c++
   Base* ptr = new Derived;  // 实际指向派生类对象
   Derived* pd = dynamic_cast<Derived*>(ptr);
   if (pd) { 
       // 转换成功，安全操作pd的派生类成员 
   } else { 
       // 转换失败，ptr未指向Derived对象 
   }
   ```

   - **原理**：利用 RTTI（Runtime Type Information）验证类型是否匹配。
   - **限制**：基类必须有虚函数表（至少一个虚函数）。

若使用 `static_cast` 进行转换：

```c++
class Base {
public:
	Base(int b) : _base(b) {}
	void print() { cout << "Base::_base = " << _base << endl; }
	// 若需使用 dynamic_cast，需至少一个虚函数
	// virtual ~Base() {} 
private:
	int _base;
};
	
class Derived : public Base {
public:
	Derived(int b, int d) : Base(b), _derived(d) {}
	void show() { cout << "Derived::_derived = " << _derived << endl; }
private:
	int _derived;
};
	
int main() {
	Base base(90);
	Derived derd(50, 40);
	
	// 不安全的向下转型(取对象地址)
	Derived* pDerd = static_cast<Derived*>(&base);
	pDerd->print();  // 可能输出垃圾值
	pDerd->show();   // 访问非法内存！
	
	// 安全的向下转型（传对象地址）
	Base* pbase = &derd;
	Derived* pDerd2 = static_cast<Derived*>(pbase);
	pDerd2->print();  // 正确访问 Base::_base
	pDerd2->show();   // 正确访问 Derived::_derived
}
```

不安全的向下转型，内存布局冲突：

- `base` 是纯基类对象，内存中仅包含 `_base` 成员。
- `Derived` 类对象的内存布局为 `[Base::_base][Derived::_derived]`。
- 当将 `Base*` 强制转为 `Derived*` 后，`pDerd` 会认为其指向的对象包含 `_derived` 成员，但实际上该内存区域不存在。

安全的向上转型：

- `pbase` 虽然类型为 `Base*`，但其实际指向的是 `Derived` 类对象 `derd`。

- `Derived` 类对象的内存布局完整包含 `Base` 和 `Derived` 的成员。
- `static_cast<Derived*>` 仅调整指针类型，不修改指针值（因基类子对象位于派生类对象起始位置）。

- 通过 `pDerd2` 访问 `_base` 和 `_derived` 均指向有效内存区域。

> [!NOTE]
>
> 若无法使用 `dynamic_cast`（如无虚函数），需严格确保 `static_cast` 的源指针实际指向目标类型。



## 派生类对象间的拷贝控制

根据 C++对象模型规则，基类的 **拷贝构造函数** 和 **拷贝赋值运算符** 不会直接被派生类继承。当处理派生类对象的拷贝操作时，需明确以下两种场景的语义：

**场景 1：派生类未显式定义拷贝控制成员**

若派生类未显式定义拷贝构造函数或拷贝赋值运算符，编译器将为其生成 **合成的（隐式）拷贝控制成员**。此时：

1. **基类部分**：调用基类的拷贝构造函数或拷贝赋值运算符（若基类显式定义）。
2. **派生类部分**：对派生类新增成员执行 **逐成员拷贝**（Member-wise Copy）。

```c++
class Base { 
public:
    Base(const Base& other) { /* 基类拷贝构造 */ } 
    Base& operator=(const Base& other) { /* 基类拷贝赋值 */ } 
};
class Derived : public Base { 
    int _derived_member;  // 派生类新增成员
}; 

Derived d1;
Derived d2 = d1;  // 调用合成的拷贝构造函数：
                  // 1. 基类部分调用 Base::Base(const Base&)
                  // 2. 派生类成员 _derived_member 执行逐成员拷贝
```

**场景 2：派生类显式定义拷贝控制成员**

若派生类显式定义拷贝构造函数或拷贝赋值运算符：

1. **基类部分**：**不再自动调用** 基类的拷贝控制成员，需在派生类成员中 **显式触发基类行为**。
2. **派生类部分**：按用户定义的逻辑处理派生类成员的拷贝。
3. 若未显式调用基类拷贝控制成员，基类部分将执行 **默认构造**（对拷贝构造函数）或 **无操作**（对拷贝赋值运算符），导致基类数据未被正确拷贝。

```c++
Derived(const Derived& other) : Base(other) { /* 派生类成员拷贝 */ }

Derived& operator=(const Derived& other) {
    Base::operator=(other);  // 显式调用基类拷贝赋值
    _derived_member = other._derived_member;
    return *this;
}
```

> [!NOTE]
>
> **总结**：
>
> | 派生类定义状态       | 基类拷贝行为触发方式 | 派生类成员拷贝方式 |
> | :------------------- | :------------------- | :----------------- |
> | 未定义拷贝控制成员   | 自动调用基类版本     | 合成的逐成员拷贝   |
> | 显式定义拷贝控制成员 | 需在派生类中显式调用 | 按用户定义逻辑处理 |



## 禁止拷贝

在 C++ 中，若将基类的 **拷贝构造函数** 和 **拷贝赋值运算符** 声明为私有成员，则派生类对象将 **完全无法进行拷贝或赋值操作**。这是因为：

1. **隐式生成的派生类拷贝控制成员失效**
   - 当派生类未显式定义拷贝构造函数或拷贝赋值运算符时，编译器会隐式生成这些成员函数。
   - 隐式生成的派生类拷贝构造函数会尝试调用基类的拷贝构造函数，隐式生成的拷贝赋值运算符会尝试调用基类的拷贝赋值运算符。
   - 由于基类的这些成员是私有的，派生类无法访问，导致编译错误。
2. **显式定义的派生类拷贝控制成员仍不可用**
   - 即使派生类显式定义拷贝构造函数或拷贝赋值运算符，也无法通过初始化列表或作用域运算符调用基类的私有拷贝控制成员。
   - 任何尝试显式调用基类私有拷贝构造函数或赋值运算符的操作都会直接触发编译错误。

```c++
class NonCpyable {
public:
	NonCpyable() {}
	~NonCpyable() {}
private: // 设为私有
	NonCpyable(const NonCpyable &rhs);
	NonCpyable& operator=(const NonCpyable &rhs);
};

void test() {
	Example e1;
	Example e2 = e1; // 拷贝构造 error

	Example e3;
	e3 = e1;	// 拷贝赋值 error
}
```
