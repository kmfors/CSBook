在设计上，**`main` 函数（或程序的入口代码区）本质上是“客户端代码”**，也就是 **调用方（Client）的使用区**。因此，在编写 `main` 函数时，必须始终 **站在 Client 的角度** 去思考，遵循以下关键原则：

1. **Client 不应关心底层实现**
   - 在 `main` 中，代码应该关注 **“要做什么”**，而不是 **“如何做”**。
   - 例如，使用 **工厂模式** 创建对象，而不是直接 `new` 具体类。
2. **代码要直观、简洁，符合业务逻辑**
   - `main` 函数的代码应该像 **“讲故事”** 一样，清晰表达程序的流程，而不是陷入技术细节。
   - 例如，使用 **观察者模式** 时，`main` 只需要注册观察者，而不需要关心通知机制如何实现。
3. **依赖抽象，而非具体实现**
   - `main` 应该依赖 **接口、基类或高层模块**，而不是直接依赖底层细节。
   - 例如，使用 **单例模式** 时，Client 只需调用 `ConfigManager::getInstance()`，而不关心它如何保证线程安全。
4. **避免在 `main` 中处理复杂初始化或依赖管理**
   - 如果 `main` 里充斥着 `new`、`if-else` 初始化逻辑，说明设计有问题。
   - 应该使用 **依赖注入（DI）** 或 **Builder 模式** 来封装这些细节。
