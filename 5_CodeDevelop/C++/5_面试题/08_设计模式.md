以下是 C++ 中五种常见设计模式的简要说明、特点及实现示例：

---

## 单例模式 (Singleton)
**特点**：确保一个类只有一个实例，并提供全局访问点。  
**实现**（懒汉式，线程安全版本）：

```cpp
#include <mutex>

class Singleton {
private:
    static Singleton* instance;
    static std::mutex mtx;
    Singleton() {} // 私有构造函数

public:
    Singleton(const Singleton&) = delete; // 禁止拷贝
    Singleton& operator=(const Singleton&) = delete; // 禁止赋值

    static Singleton* getInstance() {
        std::lock_guard<std::mutex> lock(mtx);
        if (instance == nullptr) {
            // 可能发生指令重排
            instance = new Singleton();
        }
        return instance;
    }
};

// 初始化静态成员
Singleton* Singleton::instance = nullptr;
std::mutex Singleton::mtx;

// 使用
Singleton* obj1 = Singleton::getInstance();
Singleton* obj2 = Singleton::getInstance();
// obj1 == obj2
```

## 工厂模式 (Factory)
**特点**：将对象创建逻辑封装，客户端通过工厂类创建具体对象。  
**实现**（简单工厂示例）：
```cpp
#include <iostream>
#include <memory>

// 抽象产品
class Product {
public:
    virtual void use() = 0;
    virtual ~Product() = default;
};

// 具体产品A
class ConcreteProductA : public Product {
public:
    void use() override { std::cout << "Using Product A\n"; }
};

// 具体产品B
class ConcreteProductB : public Product {
public:
    void use() override { std::cout << "Using Product B\n"; }
};

// 工厂类
class Factory {
public:
    static std::unique_ptr<Product> createProduct(const std::string& type) {
        if (type == "A") return std::make_unique<ConcreteProductA>();
        if (type == "B") return std::make_unique<ConcreteProductB>();
        throw std::invalid_argument("Unknown product type");
    }
};

// 使用
auto product = Factory::createProduct("A");
product->use(); // 输出 "Using Product A"
```

## 观察者模式 (Observer)
**特点**：定义一对多依赖关系，当主题对象状态变化时，自动通知观察者。  
**实现**：
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// 观察者接口
class Observer {
public:
    virtual void update(const std::string& message) = 0;
    virtual ~Observer() = default;
};

// 主题（被观察者）
class Subject {
private:
    std::vector<Observer*> observers;

public:
    void attach(Observer* observer) {
        observers.push_back(observer);
    }
    void detach(Observer* observer) {
        observers.erase(std::remove(observers.begin(), observers.end(), observer), observers.end());
    }
    void notify(const std::string& message) {
        for (auto observer : observers) {
            observer->update(message);
        }
    }
};

// 具体观察者
class ConcreteObserver : public Observer {
public:
    void update(const std::string& message) override {
        std::cout << "Received: " << message << "\n";
    }
};

// 使用
Subject subject;
ConcreteObserver obs1, obs2;
subject.attach(&obs1);
subject.attach(&obs2);
subject.notify("Hello Observers!"); // 所有观察者收到通知
```

## 适配器模式 (Adapter)

**特点**：将一个类的接口转换成客户端期望的另一个接口。  
**实现**（类适配器，通过多重继承）：
```cpp
#include <iostream>

// 目标接口（客户端需要的接口）
class Target {
public:
    virtual void request() = 0;
    virtual ~Target() = default;
};

// 被适配者（已有但接口不兼容的类）
class Adaptee {
public:
    void specificRequest() {
        std::cout << "Adaptee's specific request\n";
    }
};

// 适配器
class Adapter : public Target, private Adaptee {
public:
    void request() override {
        specificRequest(); // 调用被适配者的方法
    }
};

// 使用
Target* target = new Adapter();
target->request(); // 输出 "Adaptee's specific request"
```

## 装饰器模式 (Decorator)
**特点**：动态地为对象添加额外职责，避免子类爆炸。  
**实现**：
```cpp
#include <iostream>

// 组件接口
class Component {
public:
    virtual void operation() = 0;
    virtual ~Component() = default;
};

// 具体组件
class ConcreteComponent : public Component {
public:
    void operation() override {
        std::cout << "ConcreteComponent operation\n";
    }
};

// 装饰器基类
class Decorator : public Component {
protected:
    Component* component;
public:
    Decorator(Component* c) : component(c) {}
    void operation() override {
        if (component) component->operation();
    }
};

// 具体装饰器
class ConcreteDecorator : public Decorator {
public:
    ConcreteDecorator(Component* c) : Decorator(c) {}
    void operation() override {
        Decorator::operation();
        addedBehavior();
    }
    void addedBehavior() {
        std::cout << "Added behavior by decorator\n";
    }
};

// 使用
Component* component = new ConcreteComponent();
Component* decorated = new ConcreteDecorator(component);
decorated->operation();
// 输出：
// ConcreteComponent operation
// Added behavior by decorator
```

## 关键区别总结
1. **单例**：全局唯一实例（如配置管理器）。
2. **工厂**：封装对象创建（如根据不同条件创建不同数据库连接）。
3. **观察者**：事件通知机制（如GUI事件处理）。
4. **适配器**：接口转换（如将旧库接口适配到新系统）。
5. **装饰器**：动态扩展功能（如为流添加压缩/加密功能）。



### 单例模式
1. **如何实现线程安全的单例模式？**  
   - 考察点：双重检查锁（DCL）、C++11的`std::call_once`或局部静态变量（Meyer's Singleton）。  
   - 示例答案：  
     ```cpp
     // C++11 线程安全实现（局部静态变量）
     class Singleton {
     public:
         static Singleton& getInstance() {
             static Singleton instance;
             return instance;
         }
         Singleton(const Singleton&) = delete;
         Singleton& operator=(const Singleton&) = delete;
     private:
         Singleton() = default;
     };
     ```

2. **单例模式的缺点是什么？**  
   - 回答方向：  
     - 全局状态难以测试（如单元测试中无法隔离）。  
     - 可能违反单一职责原则（既管理实例又处理业务逻辑）。  
     - 多线程环境下需额外处理同步问题。

---

### 工厂模式
1. **简单工厂、工厂方法、抽象工厂的区别？**  
   - **简单工厂**：一个工厂类根据参数创建不同产品（如上面的`AnimalFactory`）。  
   - **工厂方法**：每个产品对应一个工厂类（通过子类决定实例化哪个类）。  
   - **抽象工厂**：创建产品族（多个关联产品，如跨平台的UI组件库）。

2. **为什么用工厂模式而不是直接`new`？**  
   - 回答方向：  
     - 解耦客户端和具体类（客户端只依赖抽象接口）。  
     - 便于扩展（新增产品时只需修改工厂类）。  
     - 集中控制创建逻辑（如对象池、缓存）。

---

### 观察者模式
1. **观察者模式如何解决内存泄漏问题？**  
   - 回答方向：  
     - 使用弱引用（如C++的`weak_ptr`）避免主题持有观察者的强引用。  
     - 在析构时主动调用`detach`（如RAII管理观察者生命周期）。

2. **观察者模式和发布-订阅模式的区别？**  
   - **观察者**：主题直接调用观察者的方法（紧耦合）。  
   - **发布-订阅**：通过消息队列/中间件解耦（发布者和订阅者不直接交互）。

---

### 适配器模式
1. **适配器模式和代理模式的区别？**  
   - **适配器**：解决接口不兼容问题（如将旧API适配到新接口）。  
   - **代理**：控制访问（如懒加载、权限校验），接口通常与原对象一致。

2. **类适配器和对象适配器如何选择？**  
   - **类适配器**：通过多重继承实现（需支持多继承的语言，如C++）。  
   - **对象适配器**：通过组合实现（更灵活，推荐优先使用）。

---

### 装饰器模式
1. **装饰器模式和继承的区别？**  
   - 回答方向：  
     - 继承是静态扩展（编译时确定），装饰器是动态扩展（运行时组合）。  
     - 装饰器避免子类爆炸（如组合多个功能时只需嵌套装饰器）。

2. **装饰器模式在STL中的应用？**  
   - 示例：`std::stack`底层默认使用`std::deque`，但可以通过模板参数替换为`std::vector`（类似装饰器的思想）。

### **综合应用题**
1. **设计一个日志系统，要求支持文件日志、网络日志，并能动态添加时间戳或加密功能。**  
   - 考察点：**装饰器模式**（扩展功能） + **工厂模式**（创建不同日志类型）。

2. **如何实现一个跨平台的UI库，支持Windows和Mac的按钮、文本框？**  
   - 考察点：**抽象工厂模式**（每个平台对应一个工厂类）。

3. **电商系统中，订单状态变化时如何通知库存和物流模块？**  
   - 考察点：**观察者模式**（订单是主题，库存和物流是观察者）。

---

### **高频陷阱问题**
- **单例的线程安全实现中，为什么DCL需要`volatile`？（C++中已废弃，应使用`std::atomic`或局部静态变量）**  
- **装饰器模式是否会增加性能开销？（是，因多层嵌套调用）**  
- **观察者模式中，如果通知时观察者抛异常怎么办？（需捕获异常，避免中断其他观察者）**
