## 解释命名空间

命名空间：C++中用于代码组织的一种机制，通过将变量、函数、类等封装在特定名称范围内，避免命名冲突。  

作用：防止全局作用域的命名污染、提高代码可读性和模块化

访问命名空间中的成员：

- **using 指令**（引入整个命名空间）
- **作用域解析符**（显式访问）
- **using 声明**（引入特定成员）

> [!TIP]
>
> **嵌套命名空间**：命名空间内定义其他命名空间。  
>
> **匿名命名空间**：将成员限定在当前文件内（内部链接性）
>
> 匿名命名空间与 static 的区别： 
>
> - 匿名命名空间可封装类、变量、函数等，`static` 仅限变量和函数。  
> - 匿名命名空间是 C++ 推荐的方式（更符合面向对象设计）。

## 类和结构体的区别

- 成员访问权限：

  - 类默认的：private

  - 结构体默认：public

- 设计意图：

  - 类：表示复杂行为的抽象封装，强调面向对象设计
  - 结构体：表示简单数据的聚合

## 变量的声明与定义的区别

- 声明：编译器表明变量的 **存在和类型**，但不分配内存。
- 定义：分配内存并初始化变量，实现声明的承诺。



## 全局变量与局部变量的区别

全局变量：

- 定义在函数或类外部，**整个程序可见**
- 生命周期：程序开始至结束，可在多个源文件中通过 `extern` 声明共享
- 存储位置：存储在全局静态区
- 初始化：默认初始化为 0 或 nullptr，初始化在程序启动时完成
- 使用场景：需要跨函数/文件共享的数据

局部变量：

- 定义在函数或代码块内部，**仅限所在块内有效**
- 生命周期：限于作用域范围，离开作用域后无法访问
- 存储位置：存储在栈内存
- 初始化：默认初始化未定义，每次进入作用域时重新初始化
- 使用场景：临时计算、函数内部状态管理



## 结构体是否可以直接赋值

| **场景**                 | 是否支持直接赋值 | 说明                           |
| :----------------------- | :--------------- | :----------------------------- |
| 默认结构体（无特殊成员） | ✅ 支持           | 编译器隐式生成拷贝赋值运算符   |
| 含引用成员               | ❌ 不支持         | 引用不可重新绑定               |
| 含不可拷贝成员           | ❌ 不支持         | 如 `mutex`、`unique_ptr` 等    |
| 用户删除赋值运算符       | ❌ 不支持         | 显式禁用拷贝赋值（`= delete`） |
| 自定义赋值运算符         | ✅ 支持           | 通过 `operator=` 重载实现      |

## float 如何与零值比较

**浮点数不能直接用 `==` 比较零值**（精度问题），应使用范围判断：

```c++
float f = 0.0f;
const float EPSILON = 1e-6; // 根据精度需求调整

if (std::abs(f) <= EPSILON) { /* 视为零 */ }
if (std::abs(f) > EPSILON)  { /* 非零 */ }
```

C++11 后可用 `std::fpclassify` 更精确判断：

```c++
#include <cmath>
if (std::fpclassify(f) == FP_ZERO) { /* 严格为零 */ }
```



## 引用与指针的区别

- 引用：
  - 引用为对象起了一个别名，对引用的修改操作等同于就是对对象本身的修改，引用与对象访问的地址是相同的
  - 引用在定义时，必须要绑定一个实体进行初始化，不能单独存在；并且引用一经绑定后，就不能改变绑定的对象
  - 通常无额外内存开销（符号表实现）
- 指针：
  - 用来存储内存地址，指向一个对象，意为指向一个对象的内存地址
  - 指针可以初始化为空或指向一个对象，可以修改指向的对象
  - 通常本身占用 8 个字节的内存



## const 关键字作用

在 C++ 中，`const` 用于定义 **不可修改的常量** 或 **保护数据不被意外修改**，提高代码的安全性和可读性。

**编译时常量替换（常量传播）**：

- 当 `const` 变量以编译时常量表达式初始化时（如 `const int x = 10;`），编译器会进行常量传播优化，直接替换变量为它的值（类似宏替换，但类型安全）。
- 如果 `const` 变量的初始化值不是编译时常量（如运行时才能确定的值），则不会触发常量传播

**默认内部链接（const 全局变量）**：

- 默认情况下，`const` 全局变量具有内部链接（仅在当前文件可见），因此多个文件可以定义同名变量（独立）而不会冲突。

**常量成员函数**：

- `const` 成员函数表示该函数不会修改对象的非 `mutable` 数据成员

**外部链接（extern 声明的 const 全局变量）**：

- 用 `extern` 声明的 `const` 全局变量具有外部链接，可以在多个文件中共享。
- 必须在一个文件中定义，其他文件用 `extern` 声明。
- 定义时必须加 `extern`，否则变量默认是内部链接，其他文件无法通过 `extern` 正确链接到它。

> [!NOTE]
>
> | 特性                     | 普通全局变量（非 `const`） | `const` 全局变量         |
> | :----------------------- | :------------------------- | :----------------------- |
> | **默认链接性**           | 外部链接（external）       | 内部链接（internal）     |
> | **多个文件定义同名变量** | 冲突（ODR 违规）           | 不冲突（独立变量）       |
> | **如何跨文件共享**       | 默认支持                   | 必须显式加 `extern`      |
> | **能否放在头文件**       | 不能（导致重复定义）       | 可以（每个文件独立副本） |



## 指针常量与常量指针区别

```c++
int a = 10;
const int *p1 = &a; // 常量指针，无法修改对象值，可以改变指向
int* const p2 = &a; // 指针常量，无法改变指向，可以修改对象值
```



## #define 与 const 之间的区别

#define：预处理阶段的文本替换，无类型检查，比较难调试

const：编译阶段的常量替换，有类型检查，符号保留可以调试

## constexpr 关键字作用

使用 constexpr 声明的变量或函数可以在编译时求值，优化运行时性能，类型安全

## static 关键字作用

- 静态局部变量：
  - 生命周期时整个程序运行期间
  - 作用域受限于函数内（仅函数内访问）
  - 默认初始化为 0
- 静态全局变量或函数：
  - 限制作用域于当前文件内（内部链接）
- 静态数据成员（特有）
  - 所有类实例共享同一变量，不属于任何单个对象
  - 必须在类外定义
- 静态成员函数（特有）
  - 只能访问静态数据成员
  - 没有 this 指针，不需要对象实例即可用类名调用

## extern 关键字作用

在 C++ 中，`extern` 是一个关键字，主要用于声明变量或函数的外部链接性（external linkage），其核心作用是告诉编译器某个实体（变量或函数）的定义在其他编译单元中，当前文件只是引用它。

- **声明全局变量在其他文件中定义**
  - 当变量在一个文件中定义，且需要在其他文件中使用时，可以用 `extern` 声明该变量
- **声明函数具有外部链接**
  - 默认情况下，函数本身具有外部链接性，但显式使用 extern 可以强调其跨文件可见性
- **兼容 C 代码编译**
  - 在 C++ 中调用 C 代码，需要用 `extern "C"` 告诉编译器按 C 语言的规则处理
- **修饰 const 全局变量**
  - `const` 全局变量是仅当前文件可见，若需跨文件共享，需显式用 `extern` 声明

## volatile 关键字作用

它告诉编译器：**该变量的值可能会在程序控制之外被意外修改**，因此编译器不能对这个变量进行某些优化。它的核心作用是 **强制编译器每次访问该变量时都直接从内存读取或写入，而不是使用寄存器中的缓存值**。

## mutable 关键字作用

用于修饰类的数据成员，允许在 `const` 成员函数中修改特定的数据成员。

典型使用场景：

- 缓存计算结果：数据成员的计算结果一经缓存后，不再改变
- 线程安全（锁管理）：`std::mutex` 通常声明为 `mutable`，因为锁的获取和释放在逻辑上不改变对象状态，但技术上需要修改。
- 调试或日志记录

## thread_local 关键字作用

声明线程局部变量，让每个线程有独立副本，线程之间互不干扰。

## 解释内联函数

内联函数是 C++ 中的一种函数优化机制，通过在编译时将函数代码直接嵌入到调用处，避免了函数调用的开销。

- **性能优化**：消除函数调用开销，适合短小且频繁调用的函数。
- **替代宏**：比宏更安全（类型检查、避免副作用）。
- **头文件定义**：允许在头文件中直接定义函数（避免链接错误）。

## nullptr 与 NULL 的区别

首先，`nullptr` 和 `NULL` 都用于表示空指针。

NULL：

- `NULL` 是 C/C++ 传统的空指针表示方式，通常是一个宏定义
- 类型不安全，`NULL` 本质上是整数 `0`，空指针类型可能被隐式转换为整型，导致函数重载歧义
- 在 C 中，`NULL` 是 `(void*)0`，而在 C++ 中直接赋值给非 `void*` 指针会报错。

nullptr:

- 明确表示“空指针”，而非整数 `0`
- `nullptr` 是 `std::nullptr_t` 类型，只能隐式转换为指针类型
- 可隐式转换为任何指针类型（`int*`、`char*` 等），但不能转为非指针类型。

## 函数重载的原理

函数重载是 C++ 允许在 **同一作用域内** 定义多个 **同名函数**，但它们的 **参数列表（参数类型、个数或顺序）必须不同**。编译器根据调用时提供的实参来决定调用哪个版本。

- **重载必须在同一作用域**（如全局或同一个类内）。
- **派生类会隐藏基类的同名函数**（即使参数不同），除非使用 `using` 声明。

C++ 编译器在编译时会对函数名进行 **名称修饰**，生成唯一的内部标识符，编码以下信息：函数名、参数类型、命名空间、类名（成员函数）

## 值传递、引用传递、指针传递

- 值传递
  - 将实参的副本传给函数，函数内修改不影响原数据。
  - 拷贝大对象时，存在性能开销
- 引用传递
  - 直接传递实参的别名，函数内对别名的操作等同于对实参操作。
  - 无拷贝，直接操作原数据，但函数内部可能意外修改原数据
- 指针传递
  - 传递实参的地址，函数内通过解引用操作原数据
  - 需要检查形参指针是否为空

## 异常处理的工作机制

异常处理是 C++ 中处理运行时错误的机制，允许程序在遇到异常情况（如除零、内存分配失败、无效输入等）时，跳出当前执行流，并沿调用栈向上查找匹配的异常处理器。

异常处理的三个关键步骤：

- 抛出异常：使用 throw 语句在错误发生点抛出异常对象
- 捕获异常：使用 try-catch 块捕获并处理异常
- 栈展开：异常抛出后，程序沿调用栈向上寻找匹配的 catch 块，期间自动销毁局部对象

## 解释内存对齐

内存对齐是程序设计中一项关键机制，它要求数据在内存中的存储地址必须满足特定边界条件（如 2、4、8、16 字节的倍数）。其核心目的是 **提升内存访问效率** 并 **满足硬件架构的强制要求**。

结构体的对齐值是其成员中 **最大对齐值**，且总大小需是对齐值的整数倍（编译器可能插入填充字节）。

- `alignof` 运算符进行强制对齐
- `#pragma pack`（编译器指令）调整结构体对齐

## 简述 C++程序的内存分配布局

1. **栈**：自动管理，高效但容量小，存放局部数据。
2. **堆**：手动管理，灵活但易出错，存放动态数据。
3. **全局/静态区**：长期存在，分 `.data`（已初始化）和 `.bss`（未初始化）。
4. **常量区**：只读，存放字符串和全局 `const` 常量。
5. **代码区**：存储可执行指令，只读。

## 解释动态内存分配

动态内存分配是 C++ 中在程序运行时请求和释放内存的机制。它允许程序根据需要灵活地管理内存，特别适合处理大小未知或变化的数据结构。

使用 `new` 表达式进行动态内存的分配，其过程是：

1. 调用 operator new 函数，分配足够大的原始未类型化的内存，以存储指定类型的对象
2. 调用该类型的构造函数初始化对象。
3. 返回一个指向新分配并构造的对象的指针。

使用 `delete` 表达式进行动态内存的释放，其过程是：

1. 调用指针所指对象的析构函数，回收对象中可能持有的资源。
2. 调用名为 operator delete 函数释放该对象所占用的内存。

## malloc 与 new 的区别

1. 类型安全：
   - new 是类型安全的，返回的指针类型与分配的对象类型一致。
   - malloc 返回 void*，需要显式转换为所需类型。
2. 初始化：
   - new 会调用构造函数来初始化对象。
   - malloc 不会初始化内存。
3. 异常处理：
   new 在分配失败时抛出 `std::bad_alloc` 异常。
   malloc 在分配失败时返回 NULL。
4. 释放资源：
   delete 会调用对象的析构函数。
   free 不会调用析构函数。
5. 重载能力：
   new 是操作符，可以被重载。
   malloc 是标准库函数，不能被重载。

## malloc 分配内存原理

1. 检查内部空闲链表是否有合适块
2. 若找到则标记为已分配并返回
3. 若无合适块则通过 `brk`/`sbrk` 或 `mmap` 向 OS 申请更多内存
4. 将新内存加入管理结构
5. 返回合适的内存块地址

## 解释深拷贝与浅拷贝

- 浅拷贝就是将对象的指针进行简单的复制，原对象和副本指向的是相同的资源。
- 而深拷贝是新开辟一块空间，将原对象的资源复制到新的空间中，并返回该空间的地址。
- 深拷贝可以避免重复释放和写冲突。使用浅拷贝的对象进行释放后，对原对象的释放会导致内存泄漏或程序崩溃。

## 常见的内存问题

- 内存泄漏：是指程序中已动态分配的堆内存由于某种原因程序未释放或无法释放，造成系统内存的浪费，导致程序运行速度减慢甚至系统崩溃等严重后果。
- 内存溢出：指应用系统中存在无法回收的内存或使用的内存过多，最终使得程序运行要用到的内存大于能提供的最大内存，导致无法运行程序。
- 内存踩踏：即内存重叠，是指访问了不合法的地址（访问了不属于自己的地址），如果访问的地址是其他变量的地址，就会破坏别人的数据，从而导致程序运行异常。
- 野指针：野指针是指向一个已经删除的对象或未申请访问受限内存区域的指针。

## sizeof 与 strlen 的区别

`sizeof` 用于计算操作数所占内存空间的字节大小，操作数可以是数据类型、变量、表达式等，连同 `\0` 包括在内。

`strlen` 用于计算所传入字符串的长度，不包括 `\0` 在内的。

## 解释四种强制转换

- static_cast 静态强转
  - 基本数据类型之间的转换；基类与派生类之间的指针或引用转换
  - 编译时完成，无运行时开销。不安全的向下转换
- const_cast 常量转换
  - 移除变量 const 属性
- dynamic_cast 动态转换
  - 提供安全的运行时多态类型转换，具备类型检查，可安全向下转换。
  - 失败时返回 `nullptr` 或抛出 `std::bad_cast`
- reinterpret_cast 重新解释转换
  - 处理无关类型之间的转换

## 解释 RAII

资源获取即初始化：将资源的获取与对象的构造绑定，资源的释放与对象的析构绑定。通过对象的生命周期自动管理资源。

1. **构造函数中获取资源**：当对象被创建时，在其构造函数中分配或获取资源
2. **析构函数中释放资源**：当对象离开作用域被销毁时，在其析构函数中自动释放资源

无需手动释放资源，资源生命周期与对象作用域一致，即使发生异常，资源也能正确释放。

应用场景：智能指针、互斥锁、文件指针管理

## 左值和右值的区别

- 左值 (lvalue)

  - 具有持久状态的表达式（有名字的对象）

  - 可以取地址（使用 `&` 运算符）

  - 可以出现在赋值语句的左侧

  - 通常代表一个具名的、持久的内存位置

- 右值 (rvalue)

  - 临时对象、字面量、将亡值（通过 `std::move` 强制转换的、即将被移动/销毁的对象）

  - 不能取地址

  - 只能出现在赋值语句的右侧

  - 通常代表临时的、短暂的值

## 栈溢出的原因

- 递归调用过深：递归函数没有正确的终止条件，导致栈帧不停增长，最终耗尽栈空间
- 超大局部变量：在栈上分配过大的数组或结构体对象，栈空间有限（通常 1-8MB），大对象直接耗尽空间
- 深层次的函数调用链：与递归相似，主要是函数过度嵌套，函数调用层级过深
- 缓冲区溢出：写入数组时超出边界，覆盖了栈帧中的返回地址。
- 多线程环境下，栈空间不足

## 解释静态断言

静态断言：编译时断言机制，用于在编译阶段检查条件是否成立，若不成立则立即导致编译失败并输出指定错误信息。

1. **编译时检查**：在代码编译阶段立即验证条件
2. **零运行时开销**：不会生成任何实际代码
3. **强制约束**：失败会阻止编译通过
4. **类型安全**：比传统宏断言更安全

注意：可接受的表达式必须是 **编译时可确定的常量表达式**



## 静态链接与动态链接的区别

静态链接‌：

- 编译时完成‌：库代码（如.lib 或.a 文件）在编译阶段被直接嵌入可执行文件，生成独立运行的程序。‌‌
- ‌无运行时依赖‌：无需额外库文件支持，但可执行文件体积较大。‌‌
- 多程序重复加载相同库，会导致内存占用较高

‌动态链接‌：

- 运行时加载‌：仅记录库的引用信息（如.dll 或.so 文件），程序运行时由操作系统加载共享库到内存。‌‌‌‌
- ‌依赖外部库‌：需确保目标系统存在对应库文件，否则程序无法运行。‌‌
- 多程序共享同一库内存副本，内存占用较低



## 编译过程

```c++
# 预处理  （展开#）
g++ -E main.cpp -o main.i
# 编译 (生成汇编代码)
g++ -S main.i -o main.s
# 汇编 (生成机器码)
g++ -c main.s -o main.o
# 链接 （合并链接文件，确定函数和变量的内存地址，生成可执行文件）
g++ main.o -o main
```
