## 依赖注入

依赖注入的核心思想是：**一个类不应该自己创建它所依赖的对象，而应该由外部容器来提供这些依赖**。这实现了控制反转（IoC），带来了更好的解耦、可测试性和灵活性。

业务类使用引用，前提是这些资源必须由一个资源类统一管理，先回收业务类再回收资源类；使用所有权转移，move函数转移资源的所有权，业务类有必要实现对资源的释放管理，但不的业务类要实现顺序管理。

实现方式：

- 构造函数注入：在某个类的构造函数中强制要求提供所有必需的依赖。
- Setter方法注入：可以在运行时动态改变依赖，对象可能在依赖不全的情况下被使用，状态不稳定，需要在方法中检查有效性。

好的，这里为您整理了一份非常实用和常见的 GDB 命令列表，并按照功能进行分类，方便您查阅和使用。

### 启动与退出

*   `gdb <program>`: 启动 GDB 并加载可执行程序 `program`。
*   `gdb <program> core`: 使用 GDB 调试程序 `program` 和核心转储文件 `core`，用于分析程序崩溃原因。
*   `gdb -p <pid>`: 附加到正在运行的进程 ID `pid` 上进行调试。
*   `run` 或 `r`: 开始运行被调试的程序。
*   `quit` 或 `q`: 退出 GDB。

---

### 设置断点

断点是调试的核心，用于在特定位置暂停程序执行。

*   `break <location>` 或 `b <location>`: 在 `location` 处设置断点。
    *   `b main`: 在 `main` 函数入口设置断点。
    *   `b 10`: 在当前文件的第 10 行设置断点。
    *   `b file.c:10`: 在 `file.c` 文件的第 10 行设置断点。
    *   `b Class::method`: 在类的成员函数处设置断点（C++）。

*   `break ... if <condition>`: 设置条件断点，仅当 `condition` 为真时触发。
    *   `b 25 if i == 100`: 当变量 `i` 等于 100 时，在第 25 行暂停。

*   `info breakpoints` 或 `i b`: 列出所有已设置的断点和观察点。

*   `delete <breakpoint-number>` 或 `d <breakpoint-number>`: 删除指定编号的断点。
    *   `d 2`: 删除编号为 2 的断点。
    *   `delete`: 删除所有断点。

*   `disable <breakpoint-number>`: 禁用断点（断点保留但不生效）。
*   `enable <breakpoint-number>`: 重新启用断点。

*   `watch <expression>`: 设置观察点，当 `expression` 的值发生变化时暂停程序。
    *   `watch variable_name`: 非常适合跟踪难以发现的意外变量修改。

---

### 执行控制

在断点暂停后，控制程序如何继续执行。

*   `continue` 或 `c`: 继续运行程序，直到下一个断点或程序结束。
*   `next` 或 `n`: **单步执行**，执行下一行代码。**如果下一行是函数调用，会将其作为一个整体执行，不会进入函数内部**。
*   `step` 或 `s`: **单步步入**，执行下一行代码。**如果下一行是函数调用，会进入该函数内部**。
*   `finish` 或 `fin`: 继续执行，直到当前函数执行完毕并返回，然后暂停。
*   `until` 或 `u`: 继续运行，直到退出当前循环或到达指定行号。用于快速跳出循环。
*   `return`: 强制从当前函数立即返回，可以指定一个返回值。

### 查看代码与数据

在程序暂停时，检查源代码和变量状态。

*   `list` 或 `l`: 显示当前位置周围的源代码。
    *   `l 10`: 显示第 10 行周围的代码。
    *   `l main`: 显示 `main` 函数周围的代码。
    *   `l -`: 显示之前显示过的代码。

*   `print <expression>` 或 `p <expression>`: 计算并打印表达式 `expression` 的值。
    *   `p variable`: 打印变量 `variable` 的当前值。
    *   `p array[5]@10`: 打印数组从 `array[5]` 开始的 10 个元素（非常强大！）。
    *   `p /x variable`: 以十六进制格式打印变量。
    *   `p *ptr@len`: 打印指针 `ptr` 指向的数组，长度为 `len`。

*   `display <expression>`: 每次程序暂停时，自动打印表达式 `expression` 的值。
*   `info display`: 列出所有自动显示表达式。
*   `undisplay <number>`: 取消指定的自动显示。

*   `info locals`: 显示当前栈帧的所有局部变量。
*   `info args`: 显示当前函数的参数值。

*   `backtrace` 或 `bt`: 显示函数调用栈（堆栈回溯），查看程序是如何执行到当前位置的。
*   `frame <number>` 或 `f <number>`: 切换到调用栈中指定编号的栈帧，用于查看该层函数的局部变量和参数。
    *   `f 1`: 切换到上一层栈帧。

*   `whatis <variable>`: 显示变量的类型。
*   `ptype <variable>`: 更详细地显示变量的类型信息（例如结构体的定义）。

---

### 操作程序与修改

*   `set variable <var> = <value>`: 在程序运行时修改变量的值。
    *   `set variable i = 0`: 将变量 `i` 的值设置为 0。

*   `call <expression>`: 调用程序中的函数。
    *   `call my_function(42)`: 调用 `my_function` 并传入参数 42。这对于测试函数或修改程序状态非常有用。

*   `shell <command>`: 在 GDB 中执行 Shell 命令。
    *   `shell ls -l`: 列出当前目录的文件。

---

### 其他实用命令

*   `help <command>`: 查看某个 GDB 命令的帮助文档。
*   `<Enter>`: 直接按回车键，会重复执行上一个命令。这在单步调试（`n`/`s`）或连续查看代码（`l`）时非常方便。
*   `thread <thread-id>`: 在多线程程序中，切换到指定 ID 的线程进行调试。
*   `info threads`: 显示所有线程的信息。

### 一个简单的调试流程示例

1.  **启动**: `gdb ./my_program`
2.  **设断点**: `b main`
3.  **运行**: `run` (程序会在 `main` 开始处暂停)
4.  **单步**: `n` 或 `s` (一步步执行)
5.  **查看变量**: `p variable_name`
6.  **继续**: `c` (跑到下一个断点)
7.  **回溯**: `bt` (如果崩溃了，用这个查看调用栈)
8.  **退出**: `q`

建议您将这份列表保存下来，在实践中有针对性地使用这些命令，很快就会熟练。调试是一个实践性很强的技能，多用就能掌握。
