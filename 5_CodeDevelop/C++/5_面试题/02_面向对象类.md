## 面向对象和面向过程的区别

面向对象：以对象为中心，将问题分解为相互交互的对象。对象中包含数据与操作，强调的是描述实体在问题域中的角色和交互。

面向过程：以事件为中心，将问题分解为一系列线性步骤，按顺序调用函数处理步骤，数据和操作是分离的，函数处理外部数据，而非绑定到特定对象。

## 面向对象的三大特征

封装、继承、多态

## 解释什么是封装

类将数据和操作方法捆绑在一起，形成一个自包含的模块，对外隐藏对象的内部实现细节，仅暴露必要的接口供外部访问。

将数据和行为封装，对外提供接口。保护对象内部状态。

## 解释构造函数

构造函数是类的一种特殊成员函数，它没有返回值，函数名与类名相同，用于在 **创建对象时自动初始化对象**。构造函数在对象创建时由编译器自动调用，可重载。

为什么需要构造函数呢：避免未初始化对象，确保对象创建后立即处于有效状态。

> [!NOTE]
>
> - 如果没有定义 **任何** 构造函数，编译器会生成一个默认构造函数
> - 如果定义了 **带参** 构造函数，编译器不再生成默认构造函数

## 解释委托构造函数

委托构造函数，允许一个构造函数调用同一个类中的另一个构造函数来完成对象的初始化。它的核心目的是避免重复代码，提高代码复用性和可维护性。

- 委托构造函数的初始化列表 **只能调用另一个构造函数**，不能直接初始化成员。
- 委托关系可以 **链式调用**（如 `Student()` → `Student(string)` → `Student(string, int)`）。
- 委托构造函数 **不能递归调用**（如 `A()` 委托 `A()` 会导致无限循环）。

## 解释析构函数

析构函数是类的一种特殊成员函数，用于在 **对象生命周期结束时自动清理资源**。它的特点是：

1. 释放对象占用的资源，确保资源不泄漏
2. 无参数、无返回值、不能重载
3. 在对象脱离作用域、或 delete 动态分配的对象时，自动调用

## 构造与析构函数中可以抛异常吗

允许构造函数抛异常：

- 构造函数的主要职责是初始化对象，如果初始化失败（如内存不足、文件无法打开等），**抛出异常是合理的**，可以阻止创建无效对象。
- 如果构造函数抛出异常，**已成功构造的成员变量会自动调用其析构函数**（栈回滚机制），但动态分配的资源（如 `new`）需要手动释放

不允许析构抛出异常：

- 析构函数抛出异常，会导致 **异常点之后的代码无法执行**（如释放内存、关闭文件等关键操作），从而引发资源泄漏。
- 当程序抛出异常触发栈展开时，自动调用析构函数，若析构函数再抛异常，程序会因双重异常直接强制终止（调用 `std::terminate()`）



## 哪些成员是必须在初始化列表初始化

- const 成员：`const` 成员一旦初始化后不能修改，因此必须在初始化时赋值。
- 引用成员：引用必须在定义时绑定到一个对象，且之后不能修改绑定。
- 如果成员是类对象，且该类没有无参构造函数（或默认构造函数被删除），则必须显式调用其有参构造函数。
- 派生类构造时需先构造基类，若基类没有默认构造函数，必须显式调用基类的有参构造函数。

## noexcept 关键字作用

`noexcept` 用于指定函数是否会抛出异常。它的主要作用是：

- 异常规范：声明函数不会抛出任何异常
- 条件性异常规范：根据编译时条件决定是否可能抛出异常
- 运算符：作为运算符检查表达式是否可能抛出异常

> [!NOTE]
>
> 优点：
>
> - 编译器可以优化 `noexcept` 函数，因为它们不会在运行时检查异常。这可以减少运行时开销。
>
> - 明确函数的异常行为，便于代码维护。
>
> 注意：
>
> - 如果 `noexcept` 函数抛出了异常，程序会直接调用 `std::terminate()`
> - 可以在函数声明和定义中都使用 `noexcept`，但只需要在声明中指定即可
> - 析构函数默认是 `noexcept` 的
>
> 应用场景：
>
> - 移动操作：移动构造与移动赋值
> - 交换操作
> - 简单的 getter 函数

## 解释左值引用与拷贝构造

左值引用（`T&`）是一个 **别名**，必须绑定一个实体。

- 拷贝构造函数（`T(const T&)`）用于 **创建一个新对象**，其内容与原对象相同。
- 它是一个 **深拷贝**（除非类特殊处理），即完全复制数据。

## 解释右值引用与移动构造

- **右值引用（`T&&`）**：绑定到临时对象，支持资源窃取。
- **移动语义**：通过移动构造/赋值避免深拷贝，提升性能。

## 解释 `std::move` 函数

执行类型转换，使对象能够被移动而非拷贝。

- 将对象 **无条件转换** 为右值引用
  - 将左值转换为右值引用
  - 对已经是右值的表达式无影响
- 启用移动语义而非拷贝语义
- 不进行任何实际的数据移动操作

## 解释 this 指针

this 指针是一个隐含的指针，指向的是当前对象的指针。this 指针存在于每个非静态成员函数中，它指向调用该成员函数的对象实例。

注意：

- 编译器自动将 `this` 作为隐藏参数传递给成员函数
- 只能在类的非静态成员函数内部使用
- `this` 是一个常量指针（不能修改指向的对象）
- `this` 是一个右值，不能取地址

## 解释 `=default` 与 `=delete`

`=default`（显式默认），显式要求编译器生成该函数的默认实现。

1. **只能用于特殊成员函数**（构造函数、析构函数、拷贝/移动操作）
2. **在类内声明** 时函数隐式为 inline
3. **在类外定义** 时可避免 inline

`=delete`（显式删除），禁止特定函数的调用或生成。

1. **可用于任何函数**（不仅限于特殊成员函数）
2. **编译时检查**：尝试调用会直接报错
3. **比 private 声明更彻底**（private 函数还能被成员函数调用）
4. 用于禁止拷贝或隐式转换或重载

## explicit 关键字作用

`explicit` 是 C++中用于控制构造函数和转换函数行为的关键字，主要作用是 **防止隐式类型转换**。

- 禁止编译器执行隐式转换
- 只允许显式调用构造函数或转换操作

## 解释静态成员

- 静态数据成员：
  - **类级别共享**：所有类对象共享同一份静态成员变量
  - **独立存储**：不占用类对象的内存空间
  - **生命周期**：存在于程序整个运行期间
  - 必须在类外定义，默认初始化为 0
- 静态成员函数
  - **无 this 指针**：不能直接访问非静态成员
  - **类级别操作**：只能访问静态成员变量和其他静态成员函数
  - **调用方式**：可通过类名直接调用

## 成员函数可以声明为内联吗

可以的，`inline` 关键字只是对编译器的建议，编译器可能忽略。现代编译器越来越智能，即使没有 `inline` 关键字，也会自动决定是否内联函数。

- 隐式内联（在类定义内直接实现）
- 显式使用 `inline` 关键字在类外定义

## 解释什么是友元

友元是 C++中一种打破封装性的特殊机制，它允许 **外部函数或类访问某个类的私有和保护成员**。

核心特性：

- **特权访问**：友元可以访问类的所有成员，包括私有和保护成员
- **单向关系**：友元关系是单向的，不具有传递性
- **不受访问控制**：`friend` 声明不受 `public`/`private`/`protected` 区域影响

主要形式有三种：

- 友元函数
- 友元类
- 友元成员函数

## 解释什么是运算符重载

概念：它允许程序员重新定义或扩展运算符的行为，使运算符能够作用于自定义类型的对象。

目的：让自定义类型（如类和结构体）与内置类型一样，可以使用运算符进行运算或比较。

重载运算符的实现方式：

- 类的成员函数
  - 左侧操作数必须是当前类的对象，右操作数可有可无
- 非成员函数（通常为友元）形式

> [!NOTE]
>
> 不可重载的运算符：
>
> - `.`（成员访问）
> - `.*`（成员指针访问）
> - `::`（作用域解析）
> - `?:`（条件运算符）
> - `sizeof`
> - `typeid`

## 解释什么是继承

继承是面向对象程序代码复用的重要手段，允许在确保原有类特性基础上，进行拓展、增加功能、产生新的类，一般称为派生类，被派生类继承的类叫基类。

## 解释访问级别

C++提供三种继承方式，控制基类成员在派生类中的访问权限，并存在访问降级。

访问降级指的是在继承关系中，基类成员的访问权限在派生类中变得比基类中更严格（即访问范围缩小）的情况。注意，虚函数的重写 **不受访问降级影响**（仍可形成多态）

| 继承方式  | 基类 public 成员 | 基类 protected 成员 | 基类 private 成员 |
| :-------- | :------------- | :---------------- | :-------------- |
| public    | public         | protected         | 不可访问        |
| protected | protected      | protected         | 不可访问        |
| private   | private        | private           | 不可访问        |

## 访问降级的实际应用

1. 接口限制：只允许派生类使用查询接口等等
2. 实现继承而非接口继承（需要复用代码但不需要多态）

```c++
class Database {
public:
    void connect();
    void query();
};

// 只允许派生类使用query功能
class QueryOnly : private Database {
public:
    using Database::query;  // 只暴露query接口
};
```



## 解释虚继承

虚继承是 C++ 中解决 **菱形继承问题** 的一种特殊继承机制，它确保在多重继承体系中，**公共基类** 只被继承一次，避免产生多个副本。

菱形继承问题：

- 成员名冲突的二义性
- 多重数据留存，浪费内存

## 解释什么是多态

多态是指通过统一的接口访问不同派生类对象时，能自动调用到对象实际类型所对应的实现。C++支持两种多态机制：

**编译时多态（静态多态）**：

- 实现方式：函数重载、运算符重载、模板（泛型编程）
- 特征：编译器在编译阶段通过函数签名（函数名+参数列表）即可确定具体调用版本
- 绑定机制：早绑定，又称静态联编

**运行时多态（动态多态）**：

- 实现方式：虚函数配合继承体系
- 特征：当通过基类指针/引用调用虚函数时，具体调用的函数版本需在运行时根据对象实际类型决定
- 绑定机制：晚绑定，通过虚函数表（vtable）机制实现动态联编

## 解释虚函数

虚函数是 C++实现运行时多态的核心机制，它允许派生类重写基类的函数实现，并通过基类指针/引用调用时执行派生类的版本。

虚函数是通过 `virtual` 关键字声明的成员函数，用于实现 **动态绑定**（运行时多态）。

- 派生类函数签名必须于基类的虚函数签名完全相同
- C++11 可用 `override` 关键字明确表示重写

## 解释静态联编与动态联编

静态联编(Static Binding)和动态联编(Dynamic Binding)是 C++中函数调用的两种不同绑定方式，它们决定了程序在何时确定具体要调用的函数实现。

1. 静态联编（早期绑定）

- **编译时** 确定函数调用
- 基于变量/表达式的 **静态类型**
- 默认的函数调用方式
- 高效但灵活性较低

2. 动态联编（晚期绑定）

- **运行时** 确定函数调用
- 基于对象的 **实际类型**
- 通过虚函数机制实现
- 灵活性高但有额外开销

## virtual 关键字作用

它用于声明虚函数，允许派生类重写基类的函数实现。

- 虚函数声明
- 虚析构函数，包含虚函数的类应该将析构函数也声明为 virtual
- 纯虚函数（创建抽象类）

## override 关键字作用

用于显式标记派生类虚函数的重写。

1. **明确表示重写意图**：显式声明该函数旨在重写基类虚函数
2. **编译器检查**：确保函数签名与基类虚函数完全匹配，否则编译报错
3. **代码可读性**：清晰标识类继承关系中的函数重写

使用规则：

1. **必须用于虚函数重写**（基类有对应 virtual 声明）
2. **函数签名必须完全一致**（包括 const、引用限定等）
3. **只能用于类定义内部**（不能在类外定义时使用）

## final 关键字作用

用于限制类或虚函数的继承和重写。

- 当 `final` 用于类时，表示该类 **不能被继承**（即不能有派生类）。
- 当 `final` 用于虚函数时，表示该虚函数 **不能在派生类中被重写**（override）。

## 解释纯虚函数和抽象类

- 纯虚函数是一个在基类中 **声明但没有实现** 的虚函数，派生类必须重写它，在虚函数声明后加上 `= 0`。
- 包含至少一个纯虚函数的类称为 **抽象类**。抽象类 **不能直接创建对象**，只能作为基类被继承。

## 重载、隐藏、重写的区别

重载（Overload）定义：

- **同一作用域内**，函数名相同但 **参数列表不同**（参数类型、个数、顺序不同）。
- **返回值类型可以不同**，但仅返回值不同不构成重载。

重载（Overload）特点：

- 必须在 **同一个作用域**（如同一个类或命名空间）。
- 仅参数列表不同，**与返回值无关**。
- 编译时决定调用哪个函数（**静态绑定**）。

---

隐藏（Hide）定义：

- **派生类定义了与基类同名的函数（无论参数是否相同）**，导致基类的同名函数被隐藏。
- **即使参数不同，基类函数也会被隐藏**（除非使用 `using` 引入基类函数）。

隐藏（Hide）特点：

1. 发生在 **继承体系** 中，**派生类函数隐藏基类同名函数**。
2. **不要求虚函数**，普通函数也会隐藏。
3. 如果基类函数被隐藏，**必须通过 `基类::函数名` 显式调用**。

避免隐藏：使用 `using` 引入基类函数，相当于把同名的函数重载引进来

---

重写（Override）定义：

- **派生类重新定义基类的 `virtual` 虚函数**，要求：
  - 函数名、参数列表、返回值 **完全相同**（协变返回类型除外）。
  - 基类函数必须是 `virtual`。
- 用于实现 **运行时多态**（动态绑定）。

重写（Override）特点：

1. 必须发生在 **继承体系** 中。
2. 基类函数必须是 `virtual`。
3. 使用 `override` 关键字可以显式检查是否成功重写。

## 构造函数可以声明为虚函数吗

构造函数不能为虚函数：如果构造函数是虚函数，则需要通过 vptr 查 vtable 进行动态绑定，但 vptr 的初始化又依赖构造函数执行。

## 基类析构为什么声明为虚函数

这是为了确保在通过基类指针删除派生类对象时，除了能释放掉派生类的资源，也能释放掉基类资源，避免内存泄漏和未定义行为。

## 内联成员函数可以声明为虚函数吗

语法上允许，但实际行为受限，实际上：

- 如果函数被 **实际内联展开**（由编译器决定），它将失去虚函数的动态绑定特性。因为内联优化原因。
- 如果函数通过 **多态调用**（如基类指针调用），仍需通过虚函数表动态绑定，此时无法内联。因为无法在编译期确定具体函数

## 静态成员函数可以声明为虚函数吗

不可以，静态成员函数属于类本身，而非类的某个对象，调用时无需通过对象，并且函数内没有 `this` 指针，无法访问类的非静态成员。虚函数通过对象的 vtable 实现动态绑定，必须通过对象调用。静态成员函数没有 `this` 指针，而虚函数必须通过 `this` 指针访问 vtable，二者无法兼容。

## 多态的实现原理

C++多态的实现原理主要基于虚函数和虚函数表机制。

当类中包含虚函数时，编译器会为该类生成一个虚函数表，表中存放该类所有虚函数的地址；而类创建的每个对象内部会隐式包含一个指向 vtable 的虚指针(vptr)。在调用虚函数时，程序会通过对象的 vptr 找到对应的 vtable，再根据函数在表中的偏移位置获取实际要调用的函数地址，从而实现运行时动态绑定。

通过this指针找到对象位置，再通过对象位置找到隐含的虚指针，然后再通过虚指针找到虚表。



## 初始化列表和列表顺序有关吗？

无关，成员变量的初始化顺序与它们在类定义中的声明顺序有关，而与初始化列表中的顺序无关



## 空类的大小为什么设置为 1

如果空类大小为 0，多个空类对象可能会被分配到相同的内存地址。确保了每个对象都有一个独特的内存地址
