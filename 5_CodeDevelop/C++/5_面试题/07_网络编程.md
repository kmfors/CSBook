好的，我们来简述一下 TCP 和 UDP 的区别。这是一个计算机网络的核心概念，可以从以下几个关键维度进行对比：

## TCP 和 UDP 的区别

| 特性           | TCP (传输控制协议)                           | UDP (用户数据报协议)                   |
| :------------- | :------------------------------------------- | :------------------------------------- |
| **连接性**     | **面向连接** 的协议                           | **无连接** 的协议                       |
| **可靠性**     | **可靠** 传输                                 | **不可靠** 传输                         |
| **数据传输**   | **字节流** 传输                               | **数据报** 传输                         |
| **顺序保证**   | 保证数据 **顺序**                             | 不保证数据顺序                         |
| **速度与开销** | **速度慢**，**开销大**（有确认、重传等机制） | **速度快**，**开销小**                 |
| **拥塞控制**   | 有复杂的 **拥塞控制** 机制                     | **没有** 拥塞控制                       |
| **首部大小**   | 首部较大，**20-60 字节**                      | 首部较小，固定 **8 字节**                |
| **应用场景**   | 要求 **数据完整性和准确性** 的应用             | 要求 **速度**、能容忍部分数据丢失的应用 |

1. 连接性 (Connection)

- **TCP** 是面向连接的。就像打电话，通信之前必须先通过 “三次握手” 建立一条稳定的连接通道，通信结束后还要通过“四次挥手”断开连接。
- **UDP** 是无连接的。就像发短信，你想发就发，不需要事先建立联系。每个数据包都是独立发送的。

2. 可靠性与错误恢复 (Reliability)

- **TCP** 提供可靠的传输服务。它通过 **确认应答（ACK）、超时重传、流量控制** 等机制来确保数据无误、不丢失、不重复地到达对方。如果数据包丢失，发送方会重新发送。
- **UDP** 是“尽力而为”的。它只是把数据发出去，不保证对方一定能收到。没有确认机制，也不负责重传丢失的包。

3. 数据顺序 (Ordering)

- **TCP** 会对数据包进行排序，确保接收方收到的数据顺序与发送顺序一致。即使网络中的数据传输顺序乱了，TCP 也会在接收端重新整理好。
- **UDP** 不提供任何顺序保证。后发的数据包有可能先到。

4. 传输方式 (Data Transfer)

- **TCP** 是面向 **字节流** 的。它把应用层传来的数据看成是一连串无结构的字节流，没有固定的消息边界。接收方需要自己处理“粘包”问题（即区分哪里是一个消息的结束和另一个消息的开始）。
- **UDP** 是面向 **消息** 的。每个 UDP 数据包都有明确的边界，发送多少次，接收方就会收到多少次，不会合并也不会拆分。

5. 速度和开销 (Speed & Overhead)

- **TCP** 为了保证可靠传输，需要做很多额外工作（建立连接、确认、重传、流量控制等），这些都会引入延迟和 CPU 开销，因此 **速度相对较慢**。
- **UDP** 几乎没有额外开销，非常轻量级，所以 **延迟更低、传输速度更快**。



## TCP 的主要特点是什么？

好的，TCP（传输控制协议）的主要特点可以概括为 **一种面向连接的、可靠的、基于字节流的传输层通信协议**。其核心特点如下：

- 可靠性：TCP 使用确认和重传机制来确保数据的可靠传输。它会追踪每个发送的数据段，并等待接收方发送确认信息。如果发送方未收到确认或超时，则重新发送该数据段。
- 有序性：通过序列号（seq）和确认号（ack）保证数据按发送顺序重组，解决网络乱序问题。
- 流量控制：TCP 通过滑动窗口机制来控制流量。接收方通过 **窗口字段** 动态告知可用缓冲区大小，发送方据此调整发送速率，避免接收方溢出。
- 拥塞控制：TCP 具有拥塞控制机制，以防止网络拥塞。它通过动态调整发送速率、检测丢包并减少发送速率来维护网络质量。
- 面向连接：在通信之前，TCP 需要在客户端和服务器之间建立连接。这种连接是全双工的，并且在通信结束后会释放。
- 支持多种应用层协议：TCP 不仅提供了基本的传输功能，还支持许多应用层协议（如 HTTP、FTP 等）进行高层次的通信。

### 面向连接

通信双方在传输数据之前，必须首先建立一条逻辑连接。这个过程通过著名的 **三次握手** 来实现：
1.  **SYN**：客户端发送一个 SYN 包（同步序列编号）到服务器，请求建立连接。
2.  **SYN-ACK**：服务器收到 SYN 包后，发回一个 SYN-ACK 包（确认）作为响应。
3.  **ACK**：客户端再发送一个 ACK 包进行确认。至此，连接建立成功，可以开始传输数据。

通信结束时，双方通过 **四次挥手** 来优雅地终止连接。

### 可靠性

这是 TCP 最核心的特性，通过多种机制来确保数据准确无误地送达：
*   **确认应答机制 (ACKnowledgement)**：接收方每收到一个数据包，都会向发送方返回一个确认报文（ACK），告知发送方已成功接收。
*   **超时重传机制 (Retransmission)**：发送方在发送一个数据包后会启动一个定时器。如果在规定时间内没有收到对应的 ACK 确认，发送方就认为数据包丢失，会重新发送该数据包。
*   **校验和 (Checksum)**：每个 TCP 报文段都包含一个校验和。接收方会计算校验和，如果与报文中的值不匹配，就丢弃该报文段（这间接地也会触发发送方的超时重传）。
*   **序列号与确认号 (Sequence & Acknowledgment Numbers)**：每个字节的数据都被赋予一个序列号。这不仅用于接收方按顺序重组数据，也用于接收方发送 ACK，告知发送方“我期望收到的下一个字节的序列号是什么”。

### 流量控制

TCP 使用 **滑动窗口协议** 来进行流量控制。接收方通过在其 ACK 包中通告自己的 **接收窗口大小**，来告诉发送方自己还有多少缓冲区可以接收数据。这样有效地防止了发送方发送数据过快，导致接收方缓冲区溢出的问题。

### 拥塞控制

TCP 具有复杂的算法来应对网络拥堵，避免因为发送数据过快而加剧网络拥塞。其主要算法包括：
*   **慢启动 (Slow Start)**：连接刚建立时，从一个很小的窗口开始，随着数据被成功确认，窗口大小呈指数增长。
*   **拥塞避免 (Congestion Avoidance)**：当窗口达到一个阈值（ssthresh）后，转为线性增长，以更谨慎的方式探索网络可用带宽。
*   **快速重传 (Fast Retransmit)**：当发送方连续收到 3 个重复的 ACK 时，就推断某个包丢失了，会立即重传该数据包，而不必等待超时。
*   **快速恢复 (Fast Recovery)**：在快速重传之后执行，调整窗口大小，避免突然减少数据流对网络造成冲击。

### 面向字节流

TCP 将应用程序交下来的数据仅仅看成是一连串的、无结构的字节流。它不保证接收方应用程序读到的数据块与发送方应用程序写出的数据块具有对应的大小关系。
*   **例如**：发送方应用程序分 4 次发送了 1000 字节的数据，TCP 可能会将这些数据拆分或组合成几个报文段发送。接收方的 TCP 程序会将接收到的字节流重新拼接好，放入接收缓冲区。接收方应用程序可能一次就读走了全部 1000 字节，也可能分多次读取。
*   **带来的问题**：这就是所谓的“**粘包问题**”，需要应用程序自己设计消息边界（如规定消息长度或使用分隔符）来区分不同的消息。



## 大小端

大端：高位在低地址，低位在高地址

小端：高位在高地址，低位在低地址（主机字节序，整数在内存中保存的顺序）



三次握手：

1. 客户端向服务端发送 syn
2. 服务端收到客户端的请求后，向客户端发送 ACK 与 SYN
3. 客户端收到服务端 ACK 与 SYN 后，向服务端发送 ACK

四次挥手：

1. 客户端向服务端发送 FIN，请求关闭连接
2. 服务端收到后，向客户端发送 ACK，由于服务端可能还有数据没发完，只关闭连接的读端
3. 服务端发送完所有数据后，发送 FIN，表示关闭连接的写端
4. 客户端收到后，发送 ACK，并等待持续发送 2 倍时间，确保服务端收到 ACK

`TIME_WAIT` 状态的存在是为了处理网络中延迟的旧数据包，并确保最后的 ACK 能被对方收到



## TCP网络编程

tcp的服务端编程：

1. 创建套接字
2. 设置连接IP地址与端口号
3. 绑定本机端口号：bind函数
4. 发起端口监听：listen函数
5. 接收对方连接：accept函数

tcp的客户端编程：

1. 创建套接字
2. 设置连接IP地址与端口号
3. 发起网络连接：connect函数

## UDP网络编程

udp的服务端编程：

1. 创建套接字
2. 设置连接IP地址与端口号
3. 接收对方连接：recvfrom函数

udp的客户端编程：

1. 创建套接字
2. 设置连接IP地址与端口号
3. 发起网络接连：sendto函数
